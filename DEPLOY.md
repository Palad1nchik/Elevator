# Деплой на Render — пошаговая инструкция

Результат: сайт целиком (страницы + форма заявки + API) доступен по одной
ссылке вида `https://kasper-site.onrender.com`, с HTTPS, бесплатно.
Обновление сайта после этого — просто `git push`.

## Как это устроено (важно понять один раз)

Раньше проект деплоился как **два** сервиса (фронтенд на nginx + бэкенд на Go),
которым нужно было знать адреса друг друга — на этом всё и ломалось.

Теперь собирается **один** Docker-образ (корневой `Dockerfile`):

1. Node собирает React-фронтенд в статические файлы (`dist/`).
2. Go компилирует бэкенд в один бинарник.
3. В итоговый образ попадают только бинарник + статика.

Go-сервер отдаёт и сайт, и `/api/*` с одного адреса. Поэтому: один сервис на
Render, ничего ни с чем соединять не нужно, CORS не нужен, nginx не нужен.

> **Почему раньше не собиралось вообще.** В `backend/.gitignore` была строка
> `server` — она игнорировала не только скомпилированный бинарник, но и папки
> исходников `cmd/server/` и `internal/server/`. Файл `main.go` существовал
> только на вашем компьютере и **никогда не попадал на GitHub** — Render
> клонировал репозиторий без него и падал с ошибкой
> `stat /src/cmd/server: directory not found`. Это исправлено, но поэтому
> критически важно выполнить шаг 2 (закоммитить и запушить) и шаг 3 (проверить
> файлы на GitHub).

## Шаг 1. Удалить старые сервисы на Render

Старые сервисы (`back-zekm`, `front-q4gq`) от двухсервисной схемы больше не
нужны и будут только путать.

1. Зайдите на [dashboard.render.com](https://dashboard.render.com).
2. Откройте каждый старый сервис → вкладка **Settings** → прокрутите вниз →
   **Delete Service** (Render попросит ввести имя сервиса для подтверждения).

## Шаг 2. Отправить код на GitHub

Все команды — в терминале, в папке проекта:

```bash
git add -A
git commit -m "Deploy: single-service Docker image for Render"
git push origin feature/react-go-docker-rewrite
```

Затем влейте ветку в `main` (Render по умолчанию деплоит из главной ветки):

```bash
git checkout main
git pull origin main
git merge feature/react-go-docker-rewrite
git push origin main
```

Если merge выдаст конфликты и вы не уверены, что с ними делать — можно не
вливать в `main`, а на шаге 4 просто выбрать ветку
`feature/react-go-docker-rewrite` в поле **Branch**.

## Шаг 3. Проверить, что файлы реально на GitHub

Откройте репозиторий на github.com и убедитесь, что в браузере видны:

- `Dockerfile` (в корне репозитория)
- `render.yaml` (в корне)
- `backend/cmd/server/main.go` ← раньше этого файла на GitHub **не было**
- `backend/internal/server/router.go` и `static.go`

Если их нет — вернитесь к шагу 2, деплоить бессмысленно.

## Шаг 4. Создать сервис на Render

1. [dashboard.render.com](https://dashboard.render.com) → кнопка **New +**
   (справа вверху) → **Blueprint**.
2. Если GitHub ещё не подключён — Render предложит авторизоваться и выдать
   доступ к репозиторию `Palad1nchik/Test-Elevator` (можно выдать доступ только
   к нему: Configure account → Only select repositories).
3. Выберите репозиторий из списка → **Connect**.
4. Render прочитает `render.yaml` и покажет, что создаст один сервис
   `kasper-site` (web, docker, план free). Если вы не вливали ветку в `main` —
   выберите свою ветку в поле **Branch**.
5. Нажмите **Apply** / **Deploy Blueprint**.

Больше ничего настраивать не нужно: порт, health check и переменные окружения
уже описаны в `render.yaml`. Render сам передаёт контейнеру переменную `PORT`,
и сервер слушает её.

<details>
<summary>Запасной вариант: создать сервис вручную (если Blueprint не сработал)</summary>

**New +** → **Web Service** → выбрать репозиторий, затем:

| Поле            | Значение                          |
| --------------- | --------------------------------- |
| Language        | **Docker**                        |
| Branch          | `main` (или ваша ветка)           |
| Root Directory  | оставить пустым (корень репо)     |
| Dockerfile Path | `./Dockerfile`                    |
| Instance Type   | **Free**                          |
| Environment Variables | `APP_ENV` = `production`    |

После создания: **Settings → Health Check Path** = `/api/health`.
`PORT` задавать не нужно — Render подставляет свой автоматически.

</details>

## Шаг 5. Дождаться сборки и понять, что происходит

После нажатия Deploy откроется страница сервиса. Что где смотреть:

- Вкладка **Events** — крупные этапы: "Deploy started", "Deploy live",
  "Deploy failed". Сюда смотрите, чтобы понять итог.
- Вкладка **Logs** — всё подряд: сначала лог **сборки** Docker-образа
  (скачивание node/golang, `npm install`, `npm run build`, `go build`), потом
  лог **работы** сервера.

Первая сборка занимает **5–10 минут** — это нормально (npm install медленный).
Успех выглядит так:

```
==> Your service is live 🎉
listening on 0.0.0.0:10000 (env=production)
```

Строка `listening on ...` — это уже лог нашего Go-сервера. Дальше каждая
строка вида `GET /api/health 0s` — входящие запросы (их пишет middleware
логирования). `10000` — порт, который выдал Render; так и должно быть.

## Шаг 6. Проверить сайт

URL сервиса — вверху страницы, вида `https://kasper-site.onrender.com`.

1. Откройте `https://<ваш-url>/api/health` → должно показать `{"status":"ok"}`.
2. Откройте сам сайт, пройдитесь по страницам, **обновите страницу** на
   `/obyekty` (проверка SPA-fallback — не должно быть 404).
3. Отправьте тестовую заявку на странице «Контакты».
4. Откройте `https://<ваш-url>/api/leads` → в списке должна быть ваша заявка.

## Как обновлять сайт дальше

Auto-Deploy у Render включён по умолчанию: любой `git push` в подключённую
ветку автоматически пересобирает и перевыкатывает сайт за несколько минут.
Выкатилось или нет — видно во вкладке Events.

## Особенности бесплатного тарифа (важно!)

- **Засыпание.** Без трафика 15 минут — сервис останавливается. Первый
  посетитель после паузы ждёт ~30–60 секунд, пока контейнер проснётся. Для
  теста это нормально; для боевого сайта возьмите платный план (от $7/мес) —
  тот же сервис, просто без засыпания, ничего перенастраивать не надо.
- **Заявки хранятся в памяти процесса** (`store_memory.go` — осознанное
  упрощение). Каждый деплой и каждое засыпание = список `/api/leads`
  обнуляется. То есть на бесплатном тарифе заявку легко потерять, если не
  посмотреть её быстро. Правильное решение — следующий шаг разработки:
  уведомления в Telegram/на почту при каждой заявке и/или PostgreSQL
  (на Render есть бесплатный Postgres; в коде это замена одной реализации
  `lead.Store`).

## Свой домен (например, eurasialift.kz)

1. Страница сервиса → **Settings** → **Custom Domains** → **Add Custom Domain**.
2. Render покажет, какие DNS-записи создать у регистратора домена
   (обычно `CNAME www → <ваш-url>.onrender.com` и A/ALIAS для корня).
3. После обновления DNS Render сам выпустит HTTPS-сертификат.

## Типовые ошибки

| Что видите | Причина и что делать |
| --- | --- |
| В логах `stat /src/cmd/server: directory not found` | На GitHub нет исходников бэкенда — см. шаги 2–3 (история с `.gitignore`). |
| `Deploy failed` на этапе сборки | Откройте Logs, прокрутите до первой красной/`ERROR` строки. Чаще всего падает `npm run build` — ошибка будет с именем файла и строкой. |
| `No open ports detected` | Сервер не слушает порт, который выдал Render. У нас сервер читает `PORT` из окружения — проверьте, что не задали `PORT` вручную в панели Render (удалите свою переменную). |
| Health check failed / сервис перезапускается | Проверьте, что `/api/health` открывается; смотрите Logs на панике/ошибки при старте. |
| Сайт открылся, но форма пишет «Ошибка запроса» | Откройте Logs: каждая отправка формы видна как `POST /api/leads`. Если строки нет — запрос не дошёл (проверьте `/api/health`); если есть со статусом ошибки — читайте сообщение рядом. |
| Первое открытие висит ~минуту | Не ошибка: бесплатный тариф проснулся (см. выше). |
| Пропали заявки из `/api/leads` | Не ошибка: хранилище in-memory, был передеплой или сон (см. выше). |

## Проверить локально перед деплоем (по желанию)

Локальный запуск использует **тот же самый** образ, что и Render:

```bash
docker compose up --build
# сайт:  http://localhost:8080
# API:   http://localhost:8080/api/health
```

Если здесь всё работает — на Render соберётся так же.
